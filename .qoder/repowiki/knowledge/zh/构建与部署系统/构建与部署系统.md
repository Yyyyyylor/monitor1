本项目采用多入口、多平台的构建与部署方案，核心基于 PEP 517/518（pyproject.toml + setuptools），并配套 Windows 一键安装脚本与 Docker 容器化部署。

**构建系统**
- 使用 `pyproject.toml` 作为唯一构建声明文件，依赖 `setuptools.build_meta` 作为后端，Python 版本要求 `>=3.10`，项目版本固定为 `2.1.0`。
- 包结构通过 `[tool.setuptools.packages.find] where = ["src"]` 自动发现 `src/` 下的包，测试依赖通过 `[project.optional-dependencies] dev` 提供。
- pytest 配置内嵌于 pyproject.toml：`asyncio_mode = "auto"`、`testpaths = ["tests"]`，无需额外配置文件。

**Windows 本地安装与运行**
- `install.bat` 实现零门槛安装：检测/安装 Python 3.12.9 → 创建 `venv` → 以 `-e .` 模式安装依赖（失败时回退到清华镜像）→ 复制 `.env.example` 生成 `.env` → 初始化 SQLite 数据库。
- `start.bat` 负责启动 Web 仪表盘，调用 `run_web.py`，并在缺少 venv 或 `.env` 时直接报错退出。
- `run_web.py` 是 Web 入口，异步启动 FastAPI/健康检查服务，自动打开浏览器访问 `http://localhost:8080`。

**Docker 容器化**
- `Dockerfile` 基于 `python:3.12-slim`，先复制 `pyproject.toml` 利用缓存层安装依赖，再复制源码；暴露 `/app/data` 数据卷持久化数据库与日志。
- 健康检查通过 HTTP GET `/ping` 端口 8080 验证服务存活。
- `docker-compose.yml` 定义 `monitor` 服务：映射 8080 端口、挂载 `./data` 和只读 `.env`，日志使用 json-file 驱动并限制单文件 10MB、最多 3 个轮转文件。

**运行时入口约定**
- CLI/后台监控：`python -m src.main`（由 Docker ENTRYPOINT 指定）。
- Web 仪表盘：`python run_web.py`（Windows 快捷方式）。
- 数据库初始化：`python -c "import asyncio; from src.db.database import init_db; asyncio.run(init_db())"`（由 install.bat 调用）。

**约束与规范**
- 所有依赖版本使用 `>=x,<y` 范围约束，避免上游破坏性更新。
- 开发环境必须使用虚拟环境（`venv`），生产环境通过 Docker 隔离。
- 环境变量统一通过 `.env` 加载（`.env.example` 提供模板），禁止硬编码密钥。
- 数据目录固定为 `data/`（含 `data/logs/` 子目录），确保跨平台一致。
